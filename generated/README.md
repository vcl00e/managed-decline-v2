# Generated

> **AUTO-GENERATED AREA — DO NOT MANUALLY EDIT GENERATED DOCUMENTS**

This directory contains derived views of the Managed Decline design.

The canonical source material remains:

- `../notes/` for design conversations;
- relevant `../prototypes/*/findings/` for prototype evidence and any explicitly accepted decisions recorded there;
- the repository rules in `../README.md`.

`generated/README.md` is the only hand-maintained file in this directory. All other files should be assumed to be overwritten during regeneration.

## When to regenerate

Regenerate the affected generated documents whenever:

- a note is added;
- a note is removed;
- a note is materially changed;
- relevant prototype findings are added or materially changed;
- the rules governing the generated views change.

Do **not** update a generated document by simply appending the newest material. Re-read the complete current source set and rebuild the view so later decisions can refine, subsume, supersede, or contradict earlier ones.

## Classification rules

Generated views must preserve the epistemic state of the source material. Distinguish where useful between:

- **Current accepted** — clearly accepted and not superseded.
- **Superseded / subsumed** — previously accepted but replaced or incorporated by a later accepted design.
- **Developed, not clearly accepted** — substantial design work that has not been clearly endorsed as canon.
- **Exploratory** — possibilities, examples, and speculative directions.
- **Open question** — intentionally unresolved design work.
- **Unresolved contradiction** — accepted sources conflict and chronology/context does not resolve them.

Never promote an assistant suggestion to accepted design merely because it is detailed.

## Cross-cutting material

A source concept may legitimately appear in more than one generated section.

For example, a single scenario may affect:

- narrative systems;
- world presentation;
- character performance;
- visual language;
- audio;
- progression.

That duplication is useful in the generated view because the source note itself remains canonical and singular.

## Default synthesis structure

`design-synthesis.md` should use these top-level areas:

1. Core Direction
2. Experience & Systems
3. World & Situations
4. Characters & Performance
5. Visual Language
6. Audio & Music
7. Identity & Presentation
8. Cross-System Concepts
9. Decisions & Canon
10. Open Questions / Unresolved

The purpose is to provide a current conceptual model of the project without forcing the historical notes into a production-discipline folder structure.
